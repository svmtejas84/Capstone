# RGDR implementation and synthetic verification

`src/stpignn/rgdr.py` adds three modular functions without changing ST-PIGNN architecture or historical loss code: binary cutoff-observation reliability from `lag_is_imputed`; endpoint-product edge reliability; the reliability-weighted original directional hinge; and a reliability-weighted symmetric smoothing comparator. The final two accept predicted normalized physical concentrations, the original directed station `edge_index`, wind mask and raw distance edge attribute. The first edge attribute remains metres; `sigmoid(length/1000)` is exactly the existing geometric factor. Inputs are shape/range/finite checked, and zero eligible weight returns differentiable zero.

`tests/test_rgdr.py` checks all-one reliability against `physics_v2.batched_penalty` at 1e−7 tolerance, west-from wind selecting eastbound edges, non-directional generic control, binary and bounded weights, fully missing/zero-weight handling, finite gradients, batch-mean equivalence, deterministic fixed seed and normalized-unit scaling. The gate API accepts no target values and is computed only from cutoff flags; the data integration still requires an audit in any future fit. Command: `python -m pytest -q tests/test_rgdr.py tests/test_physics_v2.py`; **8/8 tests passed** on CPU in this session. No ST-PIGNN weight was trained or modified.

The binary gate has a serious empirical sparsity issue in training and validation masks, documented in `RGDR_VALIDATION_ONLY_RESULTS.md`. Passing unit tests establishes mathematical implementation, not predictive benefit or physical validity. A matched model-training control comparison has not been executed because the corrected ST-PIGNN weights are absent, CUDA is unavailable inside this sandbox and an unrestricted new campaign is outside authorization.
