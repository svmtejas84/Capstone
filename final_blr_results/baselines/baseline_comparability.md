# Corrected v2j architectural comparability

Source: `scripts/benchmark_v2j.py`, `scripts/summarize_benchmark_v2j.py`, `configs/benchmark_v2g.yaml`, `results/data_v2j_fit.json`, `results/benchmark_runs_v2j.csv`, and saved `results/benchmark_predictions_h*_v2j.parquet`; source branch commit at audit start `128dd0324deeb23310a93cb2aaa98f2032efb648`.

All 17 existing benchmark models have corrected-weather v2j predictions for h=1,3,6,12,24 on the same 14,583 observed test station-hour pairs per horizon. The 12 neural variants have exactly seeds 11,23,37,51,79; deterministic and Ridge baselines have one prediction. `baseline_inventory.csv` gives parameter counts, seed counts, and paths. The standalone MLP and temporal CNN have no corrected-protocol result. Model B contains a temporal component but is not a standalone CNN baseline.

The neural comparison uses 12 hourly inputs, 15 monitored stations, 18 channels (13 fitted data channels, `lag_is_imputed`, four calendar channels), the corrected half-hour weather rule, train-only fitted normalization, same-space log1p target and lag, residual prediction above the causal anchor, observed-only test targets, and explicit `window <= target-horizon` cutoff. The baseline family uses the same target pairs; Ridge uses lag, calendar and weather and has a linear output. Target cleaning is 0–500 µg/m³. Train/validation/test dates and learning rate grid are fixed in the two YAMLs. Learning rate selection was validation based. The test set has been exposed repeatedly, so these are exploratory historical comparisons.

Architectures differ deliberately: GRU-only has no graph, Vanilla GCN and ST GRU-GCN use the 4-neighbor station distance graph, original ST-PIGNN and its lambda/Laplacian controls share a 43,393-parameter backbone, and GINE–GRU uses wind and edge features with 24,705 parameters. `gine_gru_wind` is Model A without a physics penalty in this benchmark, but it is not the same backbone as `stpignn_lambda0`; its comparison with GRU/ST GRU-GCN tests architecture plus input/edge design. Model B (`adaptive_graph_st`) uses a learned graph, Model C (`stpignn_v2`) a changed backbone. They should not be interpreted as isolated physics tests. The parameter and edge/input differences preclude strict capacity-matched causal attribution.

`paired_architecture_comparisons.csv` checks exact key and target identity, averages predictions across the five fixed seeds, and computes metrics on the common pairs. It resamples UTC days 2,000 times for nominal paired MAE intervals. Negative `MAE(model)-MAE(baseline)` favors the first model. The 35 tests (seven architecture pairs × five horizons) form one retrospective exploratory Holm family. Two-sided p values come from 2,000 UTC-day sign-flip draws and are Holm adjusted. The adjusted result is a sensitivity analysis; the original fixed win/physics rules in `results/benchmark_v2j.md` and `results/lambda_check_v2j.csv` are unchanged. The sign-flip test assumes day-block exchangeability under the null and has finite 1/2001 resolution.

Original ST-PIGNN beats Vanilla GCN at h=1,3,6,12 after Holm, GRU-only at h=3,6,12, and ST GRU-GCN at h=1,3,6,12. No h=24 original-ST comparison survives Holm. It also beats lambda=0 at h=3,6,12, while h=1 has only a nominal interval and h=24 has none; this cross-horizon retrospective result does not replace the fixed h=1/24 physics check. GINE–GRU beats ST GRU-GCN at h=1 and h=12 after Holm, but not GRU-only at any horizon. Full signed results, intervals, RMSE, R², pair counts, day counts and p values are in the CSV.

The v2j benchmark saved per-seed predictions but did not save trained neural checkpoints. These comparisons are numerically recomputable from local predictions; retraining would be needed if the local prediction caches disappear. GitHub contains only tracked lightweight summaries; see archive integrity and backup limits.
