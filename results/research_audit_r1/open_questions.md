## Input-rule execution audit

`configs/benchmark_v2g.yaml:14` sets `lag_is_imputed_indicator: true`. The executed `scripts/benchmark_v2g.py:47-93` loads `data_v2g_arrays.npz`, appends `(~observed_mask)` as a time-varying indicator, and derives lag PM2.5 from `scripts/input_fix_v2g.py:26-39`, which caps imputed PM2.5 at 500 and uses training-observed-target log1p mean/SD for both lag and target. `Context.batches` at `benchmark_v2g.py:95-132` takes only windows at or before `target_index-horizon`, and trains/selects using observed immediate lags; test scoring includes all observed targets. `Context.forward` at :142-148 adds a causal last-observation persistence anchor in log1p space to each neural residual. Train-only scaling is implemented in `src/stpignn/data_v2.py:331-345`, but `Context` adds calendar and missingness indicators after loading the fitted arrays. Station means use the configured training period only. W2, W7 and v2h scripts import this Context, with LOSO rebuilding after masking the held-out station (`scripts/loso_groupdro_v2h.py:105-125`). Thus the indicator and residual path are actually executed, not merely defined.

**Noncompliance/uncertainty:** `scripts/pull_weather.py:72-95` requests `Asia/Kolkata` times, parses naive timestamps, then `src/stpignn/data_v2.py:302-304` assumes those naive values are UTC; [Open-Meteo documentation](https://open-meteo.com/en/docs/historical-weather-api) confirms requested timezone controls ISO timestamps. This probable 5h30m meteorology offset affects weather-using W2/W5/W7/v2h results derived from the rebuilt arrays. It is not a forecast-origin leak, but it weakens attribution and weather comparability. Raw API response offset was not archived; exact back-correction is not authorized. Also, test includes targets with imputed immediate lags while train/validation exclude them; W2/W7 comparisons are matched within test but deployed performance includes a shifted input regime. Neural models share the same input features in W2/W7; baseline information sets differ by construction and are identified in `scripts/benchmark_v2g.py:218+` and `results/benchmark_v2g.md`. The `lag_is_imputed_indicator` key is used descriptively in config; the actual construction is unconditional in Context.

## Model C diagnostic

`src/stpignn/models_v3.py:65-104` computes a GINE+GRU residual, plus a putative transport from a fixed 15-station directed kNN graph. Edge orientation is source→destination (`scripts/benchmark_v2g.py:80-93`). It uses `relu(wind_along)` plus positive `softplus(diffusion_raw)` times concentration difference, divided by `1+distance_km`, and averages incoming terms. The expression combines wind speed in m/s and a dimensionless learned scalar; no time step, cell area, distance-gradient discretization, or unit-consistent flux is specified. Incoming averaging and clipping to zero do not conserve mass. The source is a positive MLP of nonpollutant features `x[:, -1, :, 5:]`, not measured traffic or emissions Q. Diffusion and source are constrained nonnegative; advection is rectified. This is a numerically defined neural operation, but it is not a physically calibrated advection-diffusion-source discretization. `results/benchmark_runs_v2g.csv` records learned diffusion 0.0426–0.0495 across 25 seed/horizon runs, close to initial softplus(−3)=0.0486, and batch-last source means roughly 0.74–6.28. Source statistics are last evaluated batch only (`scripts/benchmark_v2g.py:212-214`), not station/time distributions. Model C checkpoints are absent, so full coefficient variability, source/transport magnitude ratio and inference stability cannot be reconstructed. `results/benchmark_v2g.md:101-134` shows C loses to its source/transport controls and λ=0 on required comparisons, including h=24. This is a negative result with a physically underdefined operator, not evidence of valid Q physics.

No W6 setting satisfies the prespecified joint WIN. W6 anchor modification is post-hoc and must remain labelled so. Four unscored folds are in `results/loso_unscored_folds_v2g.csv`.

W7 `scripts/lambda_sweep_v2g.py:65-109` uses the same `Context`, model factory, train function, masks, seeds and LR grid for λ=0 and λ>0, selecting LR on validation for each weight. `:114-178` verifies equal seed coverage and matched test pairs, then uses 2,000 paired UTC-day bootstrap draws. `results/lambda_sweep_v2g.csv` has all five horizons and five seeds per cell. There are 25 original-model and 25 separate Laplacian λ>0 comparisons. One original-model cell qualifies: h=6 λ=.06, ΔMAE −0.282442, CI [−0.445515,−0.136521]; it is not reproduced at other horizons or weights. Laplacian has distinct hits (h=1 λ=.3, h=12 λ=.06) and must not count as original physics support. `results/lambda_verdict_v2g.json` correctly separates these. Because LR is validation-selected separately per λ, W7 isolates the penalty within the declared training procedure, not at a common LR; multiplicity is uncorrected. A λ=0 control removes the penalty, and Laplacian changes its form (`src/stpignn/physics_v2.py:78-97`). The W7 result is weak, nonreplicated physics support rather than a robust improvement.
